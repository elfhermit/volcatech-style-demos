同一頁,兩種改法:守規則 vs 照 prompt

0805 會議指出內容頁「都是純文字 list,視覺疲勞」。實際盤點證實:一個分類頁裡 loglist 這個元件出現三次(痛點／產品／成效),連續九列長得一模一樣, 唯一的區分手段是 9px 圓點的顏色——視覺權重太低。

為什麼要開這個資料夾:會議附的優化 prompt 要求 Tailwind CSS(CDN)、 Phosphor/Lucide Icons 與淺色色票(#FFFFFF／#F8FAFC／#0F172A)。 這三項與本專案的硬性規則正面衝突:
  • 禁外部 CDN——GDPR 前提。訪客 IP 會送到第三方主機。
  • 禁框架與建置步驟——demo 必須單檔自足、能直接用瀏覽器開。
  • 色系 0731 已凍結為深色 SOC Console。
所以不在 style-3-soc/ 直接改,而是兩種做法各做一份擺在一起比。 文案完全相同、一字未改——這樣比的才是版型,不是文案。
看之前先知道:Tailwind 版需要連網才會有樣式(它從 cdn.tailwindcss.com 抓 CSS)。 斷網或 CDN 被擋時,那兩頁會退化成沒有樣式的純 HTML——這本身就是「依賴外部 CDN」的成本示範。 守規則版沒有這個問題,離線也長一樣。

分類頁(第二層)三欄對照 Compute 分類頁。現況是三段 loglist;兩份提案都把它拆成四種不同的視覺處理。

開啟 Tailwind 版

兩種做法的代價對照 視覺效果的差距沒有想像中大,差別主要在下面這幾列。

項目守規則版(inline CSS)Tailwind 實驗版
外部請求 0 個。離線可開,GDPR 前提成立。 1 個(cdn.tailwindcss.com)。訪客 IP 會到第三方;CDN 掛掉頁面就沒樣式。
JavaScript 只有選單那一行行內 handler。 頁籤需要一段 script;Tailwind CDN 本身也是 JIT 編譯器,在瀏覽器裡即時產生 CSS。
首次繪製 CSS 在 HTML 裡,沒有等待。 要等 CDN 回應並在瀏覽器編譯完才有樣式,會看到一瞬間的無樣式畫面。
色系 0731 凍結的深色 tokens,與全站一致。 淺色(slate 色階)。要採用等於解凍色系,全站 20 頁都得重做。
頁籤內容 平鋪成兩個 section:可深連結、Ctrl+F 搜得到、螢幕閱讀器順著讀。 真頁籤:版面短一半,但被收起那半 Ctrl+F 搜不到,也不能深連結。
改版成本 元件寫進各頁 inline CSS,7 個分類頁要各套一次(可用腳本批次)。 要先把整個 demo 的技術棧換掉;正式 Astro 版還得再拆一次。
視覺結果 兩邊都達成「不再是純文字 list」——卡片網格、色塊分區、hover 微互動、箭頭關聯。 差別是深色 vs 淺色的觀感,不是做不做得到。
