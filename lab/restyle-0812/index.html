同樣兩頁,兩個視覺方向:Supabase 向 vs Harness 向

來源是 docs/reports/refero_design風格範本調查_20260811.md 盤的 15 個深色風格候選。 你從中挑了 Supabase 與 Harness.io 兩個「很接近現行風格」的範本。這裡是把它們的手法 實際套在自己的頁面上之後的樣子。

本輪的定位是「吸收手法」,不是「換皮」。兩套都保留 style-3-soc 的骨架、保留琥珀主色、 保留 IBM Plex stack,各自只在一個維度上破例——否則兩套會長得幾乎一樣,對照就沒有意義。
  • A(Supabase 向)= 色彩用量。把僅存的幾處裝飾性琥珀退成中性色。
  • B(Harness 向)= 表面與形態。背景加深(保持藍調、仍非純黑)、圓角柔化、 把 19 個 font-size 值收斂成 8 級階梯。
看之前先知道:markup 是凍結的。四個範例頁的 <main> 與正式頁 逐字節相同(只差相對路徑前綴),差別 100% 來自 <style>。 所以你在這裡看到的每一個差異都是版面造成的,不會有「這頁比較好懂是因為字被改順了」的混淆 (這個坑踩過:全域教訓簿 2026-07-30)。 範例頁左下角有一枚 mono 標記註明它不是線上版本——那也是純 CSS 的 ::after,沒有動 markup。
一個先講清楚的實測結果:琥珀本來就已經很克制。 var(--accent) 全站只出現 14–15 次,實際渲染的角色約 8 個。refero 報告把 Supabase 判定為現行風格的「強驗證」而不是替代方案——事實確認了報告是對的。所以 A 套的可動空間 本來就不大,這正是它需要被實際看過才能判斷的原因。

首頁三欄對照 門面。A 動 Built 區的 24px 琥珀標題;B 動背景、圓角與整套字級階梯。

判準表看完逐列勾 0805 的首頁兩案對照做完到現在仍未選定,CLAUDE.md 的「下一步 ①」還挂著。 這張表的用途就是讓判斷有依據,不要又變成看感覺。

判準看哪裡現況 A · Supabase 向B · Harness 向
首屏 3 秒辨識度 首頁不捲動,能不能一眼看出賣雲端＋資安＋託管 H1 clamp(36–58px),三張卡標題 21px。 與現況相同——A 完全不動 hero 排版。 H1 上看 64px、h2 收到 34px。標題層級最分明,但首屏文字佔比也最高。
長文可讀性 產品頁的 .spec 面板與 .faq 雙欄那兩段 內文 14／14.5px 混用,.spec p 是 14px。 與現況相同——A 不動字級。 內文統一 15px、卡內距 +2px。字大了,但頁面也會變長。
區塊區分度 .probs(痛點)、.uses(場景)、.trio(產品卡) 三者能不能不讀字就分出來 三層表面深度 ＋ 琥珀左邊界 ＋ 真箭頭(ADR 0001 的三個手段)。 邊界 3px→2px 且色相統一。三個手段都還在,但邊界的視覺重量降低。 表面層差加大(四層階梯),圓角 12px。深度這個手段被強化。
與 SOC 身分的距離 還像不像同一家公司的網站 基準。0731 選中 style-3 的原因就是這個冷色主控台調性。 最近。只是琥珀更少,骨架色票完全不動。 較遠。更深的底 ＋ 更軟的角。刻意不轉中性黑就是為了不丟掉冷色身分。
落地成本 選定之後要改幾個地方才能推到全站 37 頁 0。 7 條 CSS、0 個色碼值。其中 4 條在 restyle_content_20260806.py 的 BLOCK_CSS(改一處、37 檔同步),3 條在各頁基底 CSS。 約 60 條 CSS ＋ 4 個色碼值。要處理 435 次非 token 硬編色 (#111A26 250 次等)、111 次 rgba(),以及 build_gcp_pages_20260806.py 裡 136 次硬編。
硬性規則相容性 禁 glow／禁純黑／禁外部 CDN／WCAG 2.2 AA 全守。 全守,且零新增色票。依 ADR 0005 的定義完全合法,不需解凍。 禁 glow／禁 CDN／非純黑 都守。但動到 --bg 的值, 依 ADR 0005 需要先解凍才能落地。
附帶效果 已知缺口 1(下拉面板邊框對比不足)有沒有改善 --line 對 --bg = 1.47:1,未達 SC 1.4.11 的 3:1。 不變,仍 1.47:1。 提升到 約 1.56:1——仍未達 3:1,不能算修好。 --muted 則從 7.63:1 升到 8.10:1。
怎麼用這張表:兩套不是互斥的。A 的七條改動與 B 的六十條之間沒有衝突, 技術上可以只採 A、只採 B、或 A 全採 ＋ B 挑幾條(例如只收斂字級,不動背景色)。 字級收斂那一條特別值得單獨考慮——它是實質改善(19 個值收成 8 級)而不只是風格偏好, 而且不動任何色碼,依 ADR 0005 同樣不需解凍。
本輪沒有處理、但查出來的一個缺口:全站沒有任何字體檔。 1152 處 font-family 全部走 var(--sans)／var(--mono), 但 repo 裡 .woff2／.woff／.ttf／.otf 一個都沒有, 也沒有 @font-face。IBM Plex 只在訪客本機剛好裝了時才生效,否則直接 fallback 到 ui-sans-serif／system-ui。 你現在看到的畫面,和外部訪客看到的很可能不是同一套字。 本輪刻意不動字體(否則 A/B 對照會多一個變因),缺口記在 docs/design/00_現況基線_20260812.md,Astro 正式版用 @fontsource 自架解決。
