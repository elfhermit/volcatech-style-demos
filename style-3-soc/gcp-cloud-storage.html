Cloud Storage

Google Cloud · Object storage

Object storage for data that has no schema — files, images, exports and archives. The storage class sets what an object costs to keep and to read, while the API stays unchanged.

04Durability design target Engineered to a 99.999999999% (eleven nines) annual durability design target, applying to every storage class and location type.

Contact us All storage services

The problem

What teams run into without it.

Unstructured data sprawl

Backups, media, logs and exports accumulate across file servers, drives and departmental shares, with no common policy for retention or access. Nobody can say where the authoritative copy of anything lives.

Capacity planning guesswork

On-premises arrays force you to buy capacity years ahead of demand. Under-provision and projects stall; over-provision and the budget sits idle in a server room.

Archives on fragile media

Long-term records sit on tape or an ageing NAS, where restores take days and integrity is rarely verified until the day it matters.

Why teams choose it

What Cloud Storage is good at.

One API, several classes

The class an object sits in is a property of the object, not a separate service. Applications keep the same bucket, the same names and the same calls throughout.

Cost follows access pattern

Data read daily and data read once a year need not sit on the same terms. Autoclass moves objects as their access pattern changes.

Capacity you do not size

There is no volume to provision and no resize step when a bucket grows. Capacity follows what has been written rather than what was estimated at design time.

Key features

What you get, specifically.

01

Storage classes

Standard, Nearline, Coldline and Archive sit behind one API; the class sets the storage and retrieval cost.

02

Autoclass lifecycle

Objects move between classes on their own access history, without a lifecycle rule written per bucket.

03

Redundancy options

Each bucket is created with the redundancy it needs, so not every dataset has to be replicated the same way.

05

Availability commitment

Standard storage carries an availability service level agreement of 99.95% in a multi-region or dual-region and 99.9% within a single region; Nearline, Coldline and Archive are set at 99.9% and 99.0% for the same two cases.

06

Object size ceiling

A single object can reach 5 TiB whichever upload method is used, so datasets beyond that are held as several objects rather than one.

Where it fits

Three situations it is built for.

Static web assets

Images, scripts and downloads served straight from a bucket instead of from the application servers.

Analytics data lake

Raw events and exports landed in one place and read by query engines without a prior load step.

Long-term retention

Backups and media archives kept for years on a class priced for storage rather than for reads.

Choosing well

When Cloud Storage is the right call — and when it is not.

  • Object data at any scale — backups, media, exports, data lake files

    →Cloud Storage

  • Applications expect a mounted POSIX file system over NFS

    →Filestore

  • You need scheduled, immutable, application-consistent protection for VMs and databases

    →Backup and DR

  • The data will be analysed with SQL for reporting

    →BigQuery

Common questions

What evaluators ask.

01Can we keep our data inside the EU?

Yes. You choose the bucket location at creation — a single EU region, an EU dual-region or the EU multi-region — and object data is stored only within that boundary, which supports data-residency planning under GDPR.

02When should we use Filestore instead of Cloud Storage?

Cloud Storage holds immutable objects behind an API; it does not offer POSIX file semantics such as locking or hard links. When applications expect a mounted NFS share, Filestore is the better fit.

03How do storage classes affect cost?

Standard, Nearline, Coldline and Archive trade lower storage cost against retrieval charges and minimum storage durations; access remains low-latency in every class. The right mix depends on how often each dataset is read and how long it is kept. Contact us and we will map lifecycle rules to optimise placement.

04How durable is data held in Cloud Storage?

The service is designed for eleven nines of annual durability across every storage class, using redundant storage and checksum validation. Availability is defined separately and varies by storage class and location type.

05What happens if someone deletes objects by mistake — or on purpose?

Deleted objects are kept rather than discarded: on every bucket type that supports it, soft delete is on by default, holds a deleted object for seven days, and the window can be set anywhere between seven and 90 days. A restored object comes back as a live object in the same bucket, written to the Standard class whichever class it sat in before. Object versioning is a separate setting you switch on per bucket, which keeps the earlier generation each time an object is replaced or deleted; the two can run together, and we normally do.

06Can we stop records being deleted before a retention period is up?

Yes. A retention policy on the bucket blocks deletion or replacement of any object that has not yet reached the required age, and the policy can then be locked. Locking is one-way: afterwards the period can be extended but never shortened, and the policy cannot be removed at all. That is what makes it usable as evidence of a retention obligation rather than as an internal convention.

07Who holds the encryption keys?

Every object is encrypted on the server before it reaches disk, and that layer cannot be switched off. Where you need to hold the keys yourself, customer-managed keys in Cloud Key Management Service put rotation and revocation under your control, including keys held in a hardware security module or in an external key manager. Keys supplied with each request are also possible where a key must not be held in Google Cloud at all: the key is purged once the operation finishes and only a hash of it is kept to validate later requests, so keeping those keys safe is entirely your side of the arrangement.
