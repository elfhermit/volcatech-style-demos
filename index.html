0805 會後改版:三層選單、首頁兩案並存、內容頁全面區塊化

色系與版型已於 2026-07-31 定案為 Style 3(SOC Console 深色)× 原版直落,不再變動; 首頁版面已於 2026-08-05 收斂為現行版與 V1 兩案,V2／V3 封存。 這一輪落地的是選單結構、內容頁的區塊化改版, 以及 19 個 GCP 產品頁的決策支援內容(痛點／選型指引／FAQ)。

本輪已落地(全站 36 頁):
  • 選單改成三層,第一層不可點——Google Cloud / CyberSecurity / Services 改為 hover 展開的 <button>,不再點進總覽頁(入口改由下拉第一列的 Overview 提供);第二層是分類頁,第三層是產品。全站統一 Nav B(二層 flyout),不再有 Nav A。
  • 選單精簡——CyberSecurity 移除 AI-PTaaS／SecPurple,Services 移除 ISMS、Pentest、FinOps、DX。 只動選單:頁面上這六項的區塊與頁尾清單全部保留,只是不出現在下拉裡。
  • 第三層補齊為 19 頁——每個 Google Cloud 產品都有自己的產品頁, 不再有「這個點得進去、那個點不進去」的落差。骨架一致:Hero →核心優勢 3 卡 →關鍵特色 → 適用場景 → Works with 架構圖 → CTA。分類頁的每張產品卡現在有兩個出口: 站內產品頁在前、離站原廠頁在後。
  • 產品頁再加三段「決策支援」內容(08-06 晚)——參考 Google 官網產品頁的解剖結論 (吸引企業買家的是「該選哪個、適不適用、疑慮怎麼收」,不是規格),每頁新增: 痛點(導入前的問題狀態)、選型指引(什麼情境 → 選哪個產品,含誠實指向 隔壁產品的列)、FAQ(平鋪問答,可 Ctrl+F)。文案取自 Google 技術文件改寫並經 獨立稽核;全站不放金額資訊,計價問題一律 Contact us。
  • Cloud 總覽攤開全部產品——cloud.html 原本只有六個「領域」卡, 而 Cybersecurity 總覽卻是 8 個產品逐一列出,三個總覽頁的粒度不一致。 現在六領域卡留著當導覽,下面再攤開 19 個產品的索引;索引的描述句直接取自分類頁, 不另外寫一份會各自漂移的文案。
  • FortiEDR 與新增的 GCP Managed Services 尚無內頁,選單上做成不可點的灰字,標 Coming soon。
內容頁區塊化(2026-08-06 定案並落地):走守硬性規則的 inline CSS 版,Tailwind 版不採用。 舊問題是同一個 loglist 元件在一頁裡出現三次(痛點／產品／成效),連續九列長得一模一樣, 唯一的區分手段是 9px 圓點的顏色。現在每一段各有自己的處理:
  • 痛點與場景用琥珀左邊界的區塊,產品與服務用附自繪 icon、可點進子頁的卡片, 有順序的交付流程用帶真箭頭的步驟列,成效與規格用深一階的編號面板。
  • 沒有新增任何色票——區分靠三層表面深度、一道琥珀邊界與一列真箭頭,0731 的色系凍結仍然成立。 卡片加了 2px 的 hover 浮起(不加陰影,專案禁 glow),並在 prefers-reduced-motion 下關閉。
  • 文案逐字未動。這輪只改版型;docs/reports/check_copy_20260806.py 會逐句比對改版前後,少一句或多一句都擋下來。

開啟 V1
選單怎麼測:
  1. 把滑鼠移到 Google Cloud 上——它不應該可以點,只會展開下拉。
  2. 從第一層斜著移進第二層的 flyout,中途不要掉層;再試 純鍵盤 Tab 能不能走完三層。
  3. 下拉開著時按 Esc,面板應該關閉(焦點會回到左上角 logo)。
  4. 點 Compute → Compute Engine,確認進的是獨立產品頁而不是分類頁的錨點。
  5. 把視窗拉到約 1000px 寬,再開一次 Google Cloud:第二層應該改成在面板內就地展開,不會跑出畫面。
  6. 390px 手機寬:選單三層應該全部攤開成縮排清單,沒有水平捲軸。

Lab三欄對照

分類頁與產品頁的兩種改法

會議指出的問題是「內容頁都是純文字 list,視覺疲勞」。實際盤點:一個分類頁裡 loglist 出現三次(痛點／產品／成效),連續九列同一長相,只靠 9px 圓點的顏色區分。 兩種改法的差別在於要不要為了視覺而放棄單檔自足與 GDPR 前提。 結論:守規則版勝出,做法已搬進 style-3-soc/; 「分類頁現況」現在看到的就是改版後的樣子。
